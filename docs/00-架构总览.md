# 00 · 架构总览（路演版）

> 读这篇能知道：**有几个模块、它们怎么连、数据怎么流、谁是时间权威、队友C的麦怎么走**。
> 路演版核心变化：**两个数字人（Angela 女 / Neo 男）**、**队友C 现场真唱**、**数字人声离线烤制（RVC）、不做实时变声**。

---

## 1. 一句话架构

> 舞台（Web）是**总编排与渲染**：背景 MV、双声部歌词、右侧数字人（按场切换 Angela/Neo）；
> 后端（FastAPI + WS）是**音频大脑**：离线把数字人声 RVC 烤好、预混进"伴奏带"、烘焙口型/动作/歌词、WS 推流、TTS；
> 队友C 的麦克风走**调音台 PA**，与伴奏带现场混合，**数字人系统不碰这条链路**。

## 2. 两场同构：伴奏带 + 现场麦

两场结构完全一样，只是**换数字人、换曲、换声部关系**：

```
       离线烤制（队友B，5070Ti）                     现场播放
  原曲人声 ─RVC→ 数字人声 ┐                 ┌→ 伴奏带.wav ─┐
  伴奏 ──────────────────┴→ 预混 → 伴奏带.wav │              ├→ 调音台 → PA
                                              │  队友C 麦克风 ┘   (观众听)
  数字人声 ─→ 烘焙 visemes.json ─→ 数字人对口型（屏幕上，与伴奏带同源时钟）
```

| 场 | 伴奏带里有什么 | 队友C 现场唱什么 | 数字人对口型的声部 |
|----|----------------|------------------|--------------------|
| 传奇 | 伴奏 + **Angela** 女声（RVC） | 同旋律（**齐唱**） | 整条旋律 |
| 因为爱情 | 伴奏 + **Neo** 男声（RVC） | 王菲**女声部**（对唱） | 陈奕迅**男声部** |

> 因为爱情男声+伴奏已由你分好（`演示用例/因为爱情_分轨/`），女声被去掉——正好留给队友C现场。

## 3. 模块地图

```
┌──────────────────────────────────────────────────────────────────────┐
│                       packages/stage  （你 · 舞台前端）                │
│   ┌──── Orchestrator（场1传奇 → 场2因为爱情，含开场/收尾 TTS）────┐  │
│   │  ┌── MV <video> ──┐  ┌── 歌词双栏(数字人声部 / 队友C现场声部) ──┐││
│   │  │ 背景全屏        │  │ 按 t 高亮                              │││
│   │  └────────────────┘  └──────────────────────────────────────────┘││
│   │  ┌── 主时钟 <audio>=伴奏带.wav ──┐  ┌─ 数字人槽位(右侧透明) ──┐ ││
│   │  │  currentTime = 渲染权威        │  │ Angela ⇄ Neo 按场切换    │ ││
│   │  └────────────────────────────────┘  │ setViseme/playMotion     │ ││
│   └──────────────────────────────────────┴────────────────────────────┘ │
└─────────────────────────────────────────┬──────────────────────────────┘
                                          │ WebSocket（控制/事件/TTS/口型帧）+ REST
┌─────────────────────────────────────────▼──────────────────────────────┐
│                 packages/backend  （队友 B · 音频大脑）                   │
│   ┌─ 离线烤制 ──────────────────────────────────────────────────────┐  │
│   │  分轨(Demucs) → 数字人声 RVC(社区模型, 5070Ti) → 预混 伴奏带.wav   │  │
│   │  → 由数字人声算 visemes.json → 手写 actions/lyrics/scene.json     │  │
│   └────────────────────────────────────────────────────────────────────┘ │
│   ┌─ 运行时 ────────────────────────────────────────────────────────┐  │
│   │  FastAPI REST  : /api/scenes, /api/scenes/{id}, /assets/...      │  │
│   │  WebSocket /ws : scene.load / scene.start / tts.* / viseme.frame │  │
│   │  TTS           : edge-tts(+可选 RVC) → 对白音频+口型帧             │  │
│   └────────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────────┘

┌──────────────────────── 调音台 / PA （独立链路，队友C）──────────────────┐
│   队友C 麦克风 ──┐                                                      │
│                  ├─→ 调音台 ──→ PA（观众听）                            │
│   伴奏带.lineout ┘ （伴奏带同时给舞台 <audio> 和调音台一路 lineout）      │
└──────────────────────────────────────────────────────────────────────────┘
```

> **伴奏带两路输出**：① 给舞台 `<audio>`（驱动 MV/歌词/口型时钟）；② 给调音台（和队友C 麦混音给 PA）。
> 这保证**观众听到的**和**屏幕口型**同源于一个伴奏带文件 → 嘴音天然不漂。

## 4. 时间线数据流

### 开场 `intro`（每场可选）
```
后端 TTS → WS 推 tts.* / viseme.frame / subtitle → 前端播 TTS、数字人对口型、字幕
```

### 合唱 `singing`
```
前端 WS 发 scene.start
后端: 推 scene.tracks(lyrics/visemes/actions) + scene.start(backingUrl)
前端:
  <audio> 播 伴奏带.wav（★ 主时钟，渲染权威）
  每帧读 audio.currentTime:
    · 歌词双栏：定位当前行（数字人声部 / 队友C现场声部）
    · 口型：visemes.json 插值 → setViseme()
    · 动作：actions.json 查段 → playMotion()
  队友C: 在现场对着同一伴奏带真唱（麦走 PA，与屏幕独立但同源时钟）
后端: 推 scene.tick{t} 心跳（仅状态/纠偏）→ scene.end
```
> **合唱期不逐帧推口型**：抗网络抖动、嘴音零漂。visemes 是预烘焙时间轴，前端按本地音频时钟查表。

### 收尾 `outro`
```
后端 TTS（点评/致谢）→ 同 intro 实时推 → 数字人对口型 → 进入下场或结束
```

## 5. 主时钟与同步模型

| 场景 | 时间权威 | 口型来源 | 动作来源 |
|------|----------|----------|----------|
| 合唱 `singing` | 前端 `<audio>` `currentTime`（伴奏带） | 预烘焙 `visemes.json` | 预烘焙 `actions.json` |
| 对白 TTS（intro/outro） | TTS 音频播放时间 | 后端实时推 `viseme.frame` | 后端 `action.set` |

- **观众侧同步**：队友C 听的是调音台里的伴奏带 lineout，与舞台 `<audio>` 是**同一文件**，天然同源。
- **排练要点**：队友C 戴返听（监听伴奏带 + 自己），别跟屏幕延迟。

## 7. 技术决策记录（ADR）

| # | 决策 | 理由 |
|---|------|------|
| ADR-1 | 前端 Web | 跨平台、3 件套（视频+歌词+数字人）叠加最快 |
| ADR-2 | 数字人 Live2D（pixi-live2d-display） | VTuber 风格、Web 直跑、口型/动作成熟 |
| ADR-3 | 数字人是**前端组件** | 同进程，接口即 JS API |
| ADR-4 | 通信 WebSocket | 控制信令 + TTS 口型帧低延迟双向 |
| ADR-5 | 合唱渲染以**前端音频时钟**为权威 | 嘴音零漂、抗抖动 |
| **ADR-6** | **数字人声离线 RVC 烤制、不做实时变声** | 实时变声延迟/翻车风险高；离线可反复打磨 |
| **ADR-7** | **伴奏带双路输出**（舞台 + 调音台） | 观众听与屏幕口型同源、队友C 有稳定返听 |
| **ADR-8** | **队友C 麦走独立 PA 链路** | 数字人系统零负担、现场混音交给调音台 |
| **ADR-9** | **RVC 用社区现成模型、不自训** | 5070Ti 够推理、省训练时间；见 `09` 合规提醒 |
| ADR-10 | Neo = 男数字人（新增第二个模型） | 因为爱情对唱需要男声数字人 |
| ADR-11 | 两场串行、数字人**按场切换**（不同屏） | 简单；同屏双人为未来扩展 |

## 8. 非目标（本版不做）

- ❌ 实时变声 / 实时收队友C 人声做处理（队友C 只走 PA）
- ❌ 翻唱/练声/分析/角色切换模式（见概念文档后续版本）
- ❌ 自训 RVC 模型（用社区现成，见 `09`）
- ❌ 同屏两个数字人（按场切换即可）
- ❌ 移动端适配（演示机/投影）
