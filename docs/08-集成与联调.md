## 1. Drop-in 整合顺序（黄金路径）

每一步都要能独立演示，再进下一步。

| 步 | 拼什么 | 用什么数据 | 通过标准 |
|----|--------|-----------|----------|
| D1 | stage 骨架 + **mock_ws.py** | `data/samples/*` | 三幕状态机走完，歌词随 tick 滚，占位框在右侧 |
| D2 | + character 模块（任意模型） | mock visemes | 数字人在右侧动嘴、切动作，透明叠在黑底上 |
| D3 | + 真 MV 背景 | 静态图或真 mv | MV 在最底层，数字人/歌词在之上 |
| D4 | + 真 backend（TTS） | 真后端 /ws | 选歌/收尾对白有声音、口型动、字幕同步 |
| D5 | + 真 mix.wav + 真轨道 | 稻香真数据 | 合唱嘴音同步、歌词时机准 |
| D6 | + RVC Angela 音色 | 队友 B 产出 | 高声部是女声，整体像"男女合唱" |
| D7 | 演示机全量 + 兜底演练 | 全真 + Plan B | 完整走两遍，掐时间 |

> 任何一步卡住 >15min，**退回上一步**继续演示，别原地死等。`song.tracks`/`tts.*` 都有 mock 兜底。

## 2. Mock 数据（data/samples/）

仓库已带可直接用的样例（字段=合同真值）：

- `song.daoxiang.json` — 完整 manifest 样例
- `lyrics.daoxiang.json` — 几行带时间戳的歌词
- `visemes.sample.json` — 一小段口型帧
- `actions.sample.json` — 动作时间轴

前端/数字人**第一步就吃这些**，不等后端/分轨。
- 前端：把 `song.tracks` 的 url 指向 `data/samples/`，mix 用任意 wav（甚至静音）。
- 数字人：`demo.html` 加载 `visemes.sample.json` 循环播放，验证嘴动。

## 3. mock_ws.py 用法（联调利器）

`packages/backend/mock/mock_ws.py`（仓库已提供）——纯 Python、无重依赖的 mock WS：

```bash
cd packages/backend/mock
pip install websockets   # 仅此一个依赖
python mock_ws.py        # 默认 ws://localhost:8765
```
- 行为与真后端**信封/字段完全一致**（见 `02`）：
  - `hello` → 回歌单
  - `song.select` → `phase.change`+`song.loaded`+假对白（静音 TTS + 固定 viseme 帧）
  - `song.start` → `song.tracks`（指 data/samples）+`song.start`（指一个本地 wav）+10Hz `song.tick`→`song.end`→`finale` 假对白
- 前端把 `ws://localhost:8765` 当真后端连即可，切真后端只改地址。

## 4. 演示机部署（一台机跑全套）

最省事：**后端同时托管前端 + 数字人 + 静态资源**，避免跨域/跨源。

```
演示机
├─ 终端1: uvicorn app:app --host 0.0.0.0 --port 8000   # 后端 + /assets + (可选) 托管 stage
├─ 终端2: (可选) python -m http.server 5173 (在 stage)   # 或交给后端 8000 托管
└─ 浏览器全屏打开 http://localhost:8000/ (或 5173)
```
- 后端 `app.mount("/stage", StaticFiles(directory="../stage"))` 把前端挂上，访问 `/stage/index.html`。
- `packages/character` 也得在同源可访问路径下（挂 `/character` 或前端用相对路径）。
- 投影/大屏：浏览器全屏（F11），CSS 用 `vh/vw`，别写死像素。

## 5. 跨模块对齐检查表（联调前过一遍）

- [ ] WS 信封字段名三方一致（`type/seq/ts/data`，`ParamMouthOpenY` 大小写一致）
- [ ] `actions` 的 `name` 都在 `05 §4` 词表内
- [ ] `mix.wav` 与 `lyrics/visemes/actions` **同起点**（用 ffprobe 对时长）
- [ ] 数字人 canvas `z-index` 在 MV 之上、歌词之下或并列（按设计）
- [ ] 静态资源路径同源、MIME 正确（`.wav` → `audio/wav`，`.json` → `application/json`）
- [ ] CORS：若前端与后端不同源，后端开 `allow_origins`（同源则免）

## 6. 常见坑与解

| 现象 | 原因 | 解法 |
|------|------|------|
| 数字人嘴不动 | `setViseme` 没注册到模型每帧更新 / 参数名拼错 | 确认 `ParamMouthOpenY` 注册 `beforeUpdate` 钩子；打印参数值 |
| 嘴对不上声音 | 口型用了 WS tick 时钟 | 合唱期改用 `audio.currentTime` 查表（见 `06 §4`） |
| 歌词整体偏移 | mix 与 lyrics 起点不一致 | 用 mix.wav 重新打点；或在 lyrics.json 整体加 `offset` |
| 口型一直张着 | RMS 没归一/没阈值 | 后端按 0.95 分位归一；静音段强制 0 |
| 数字人挡住歌词 | z-index/定位 | canvas 右侧、歌词左移或加面板底 |
| TTS 没声音 | 浏览器自动播放策略 | 首次交互（点歌）后再播；或静音 `<audio>` 预热 |
| 模型加载 404 | 路径/同源 | 用相对路径 + 同源托管；查 Network 面板 |
| 合唱时听不到 Neo | 混音音量失衡 | B 调 `volume`；Neo 略低于 Angela 或持平 |
| 大屏掉帧 | MV 4K + Live2D | MV 降到 1080p；关浏览器硬件加速冲突项 |

## 7. 兜底预案（Plan B，务必准备）

1. **后端挂了**：前端自动转 `OFFLINE`——本地播 `mix.wav` + 本地轨道 JSON + 预录对白 wav（B 提前生成放 assets）。见 `06 §8`。
2. **RVC 来不及**：用原人声跑通；高声部"女声"用 edge-tts/原曲和声顶替，或不区分音色（流程为先）。
3. **Live2D 模型挂了**：静态 PNG 立绘 + 幅度驱动一个"嘴形图层"（CSS clip 或两张图切换）。
4. **MV 没素材**：歌词背景图 + 频谱 canvas（`AnalyserNode` 接 `mix.wav`）。
5. **演示机崩了**：**录屏备份**（C5 前录一份完整 demo 视频），现场放录像。
6. **网络/WS 抖动**：合唱期本就不依赖逐帧 WS，几乎无影响；对白期降级预录 wav。

## 8. Demo 走场脚本（现场用）

```
1. 开场（select）：Angela "今天想唱什么？" → 点《稻香》→ Angela "就让我们一起唱《稻香》吧！"
2. 合唱（singing）：MV 起，左右歌词随唱高亮，Angela 对高声部口型、轻摆 + 偶尔挥手
3. 收尾（finale）：唱完 Angela "今天唱得真不错呢，下次再一起练好不好？" + 鞠躬
```
- 计时：选歌 ~15s + 合唱 ~3min40s（可只放前两段主歌+副歌 ≈ 90s）+ 收尾 ~10s。
- **建议 demo 只放 90s 片段**（主歌+副歌），避免现场干等；完整版留录像。

## 9. 自检通过的定义

- ✅ 三幕都能完整走完，无报错。
- ✅ 合唱期嘴与声音同步（<80ms 误差，肉眼不察觉）。
- ✅ 歌词当前行与演唱对得上。
- ✅ 数字人在 MV 之上、不穿帮、不挡关键歌词。
- ✅ 断网/后端重启后能自恢复或转离线模式。
