# 05 · 数字人接入（队友 A 专篇 · 路演版）

> 你负责把**两个数字人**（Angela 女 / Neo 男）接进舞台：加载模型、按场切换、暴露 JS API、
> 用口型/动作数据驱动、在右侧透明叠层渲染。
> 路演版核心变化：**多模型 + 场间切换**（传奇用 Angela、因为爱情用 Neo，不同屏）。

参考：`00 架构`、`02 接口`、`03 数据格式`。

---

## 0. 定位

- 数字人是**前端组件**（`packages/character/`），用 **pixi-live2d-display**。
- 一次**只显示一个**数字人（按场切换），非当前场的模型可预载或卸载。
- 对外暴露稳定 API（§2），舞台通过它驱动；舞台把 WS 的 `viseme.frame`/`action.set`/`character.set` 转成 API 调用。

## 1. 环境与依赖

> **版本务必配套**：`pixi.js@7` 必须配 `pixi-live2d-display@0.5.0-beta`（其 peerDep 是 `pixi.js^7`）。
> ⚠️ 早期写的 `pixi-live2d-display@0.4` 的 peerDep 是 `@pixi/^6`，**与 pixi@7 不兼容**，二者勿混用。

```bash
cd packages/character
npm install pixi.js@7 pixi-live2d-display@0.5.0-beta   # 固定版本号，勿用 @latest
```

**无构建工具（原生 ES Modules）下用 UMD 加载**，不要走 ESM importmap —— `cubism4.es.js` 内的 `@pixi/*` 裸导入在浏览器里解析不了。
三个 `<script>` 按序加载（**cubism core 必须最先**），代码里 `const { Live2DModel } = window.PIXI.live2d`：

```html
<script src="lib/live2dcubismcore.min.js"></script>   <!-- 提供 window.Live2DCubismCore -->
<script src="lib/pixi.min.js"></script>               <!-- 提供 window.PIXI（pixi.js@7 UMD）-->
<script src="lib/cubism4.min.js"></script>            <!-- 挂到 window.PIXI.live2d（0.5.0-beta UMD）-->
<script type="module" src="demo.js"></script>
```

- 开发期可用 CDN（cubism core 官方直链 + `cdn.jsdelivr.net` 的 pixi/cubism4）；**路演前务必下到 `lib/` 本地化**（断网兜底）。
- 两个模型放 `packages/character/models/{angela,neo}/`（各含 `.model3.json`、`.moc3`、贴图、动作）。
- **男 Live2D 模型较少**：Neo 可用 VRM/3D 男模（three-vrm）或简化（PNG+口型）兜底（见 `08`）。

## 2. API 契约（多模型 + 切换）

```js
// packages/character/character.js
export class CharacterStage {
  static async mount(canvasEl)                      // 挂载，返回实例（内部 pixi app）

  async preload(name, { model })                    // 预载一个模型（angela / neo）
  async switchTo(name, { blend=0.3 }={})            // 切到某模型（淡入淡出）
  get current()                                     // 当前模型名

  setViseme(params)            // {ParamMouthOpenY:0..1, ParamMouthForm?:} 作用于当前模型
  playMotion(name, opts)       // name 见 §4 词表；作用于当前模型
  setExpression(name)
  idle()
  destroy()
}
```

舞台用法（示意，完整见 `06`）：
```js
import { CharacterStage } from '../character/character.js';
const stage = await CharacterStage.mount(document.getElementById('cv'));
await stage.preload('angela', { model:'models/angela/angela.model3.json' });
await stage.preload('neo',    { model:'models/neo/neo.model3.json' });
stage.switchTo('angela'); stage.idle();

ws.on('character.set', d => stage.switchTo(d.name));           // 场间切换
ws.on('viseme.frame',  d => stage.setViseme(d.params));        // 对白期
ws.on('action.set',    d => stage.playMotion(d.name, d));
// 合唱主循环里：stage.setViseme(visemes.lookup(t)); ...
```

## 3. 口型映射

| 参数 | 范围 | 来源 |
|------|------|------|
| `ParamMouthOpenY` | 0..1 | visemes（RMS）★必需 |
| `ParamMouthForm` | -1..1 | 固定/音素估（可选） |
| `ParamBreath` | 0..1 | 模型自驱动（idle） |

实现要点（作用于**当前模型**的 coreModel）：
- 每帧设 `setParameterValueById('ParamMouthOpenY', v)`；平滑 lerp、静音闭嘴、爆破音可过冲。
- 后端给 0..1 归一值，你按模型嘴大小调 `gain`。
- `switchTo` 时把当前口型值过渡到新模型，避免跳变。

## 4. 动作词表（= Live2D motion 组名）

| name | 必备 | 说明 |
|------|------|------|
| `idle` | ✅ | 待机呼吸+眨眼 |
| `talk` | ✅ | 对白（intro/outro） |
| `singing_high` | ✅ | Angela 唱高/女声（传奇） |
| `singing_low` | ✅ | Neo 唱低/男声（因为爱情） |
| `sway` `wave` `bow` `point` | ⬜ | 摇摆/挥手/鞠躬/指向 |

> 动作名与 `actions.json`/`action.set` 的 `name` 一一对应（`03 §4`）。缺动作用 `idle` 顶替，别报错。
> **两个模型都要准备这些 motion 组**（Angela 一套偏女、Neo 一套偏男）。

## 5. 渲染与切换

- canvas 透明：`background:transparent`，pixi `background.alpha=0`，`z-index` 在 MV 之上。
- 右侧、垂直居中、底部对齐；resize 重算 scale/position。
- `switchTo`：旧模型淡出（alpha→0）→ 切 visible → 新模型淡入；或同屏交叉溶解（更顺）。约 0.3s。
- **性能**：非当前模型可 `visible=false` 或卸载；60fps 目标；切换时避免卡顿（预载）。

## 6. 与 WS 衔接

后端 → 舞台 → 你。你只需 API 稳定；舞台负责：
- `character.set` → `stage.switchTo(name)`（场间）
- 对白期 `viseme.frame` → `setViseme`；`action.set` → `playMotion`
- 合唱期舞台按 `audio.currentTime` 查 `visemes.json`/`actions.json` → `setViseme`/`playMotion`

> 想让数字人独立连 WS 也行，但**推荐走舞台转发**，保证与歌词同源。
