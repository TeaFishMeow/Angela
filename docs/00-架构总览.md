# 00 · 架构总览

> 这是 Angela 合唱模式 MVP 的系统视图。读这篇能知道：**有几个模块、它们怎么连、数据怎么流、谁是时间权威**。
> 后续每篇文档都是对这里某一块的展开。

---

## 1. 一句话架构

> 前端舞台（Web）是**总编排与渲染**：左边播 MV、中间显示双声部歌词、右边渲染 Live2D 数字人；
> 后端（FastAPI + WebSocket）是**音频大脑**：分轨→RVC 变声→混音→生成口型/动作/歌词时间轴→推流，并负责选歌/收尾的 TTS；
> 数字人（Live2D 模块）是舞台里的一个**前端组件**，由队友 A 提供，接收口型/动作指令做表情与动作。

## 3. 三幕数据流（谁推谁）

### 幕一 · 选歌 `select`
```
用户点歌 → 前端 WS 发 song.select
后端: TTS 生成 Angela 确认语 → WS 推 tts.start / viseme.frame* / tts.end
前端: 播 TTS 音频；把 viseme.frame 转给 Live2D 模块对口型；显示对白字幕
```

### 幕二 · 合唱 `singing`
```
前端 WS 发 song.start
后端: 推 song.tracks（把 lyrics/visemes/actions 的文件路径或内联数据下发）+ song.start
前端:
  - <audio> 播 mix.wav（★ 主时钟，渲染权威）
  - 每个 requestAnimationFrame 读 audio.currentTime：
      · 歌词双栏：定位到 [t, t+d] 包含 currentTime 的行 → 高亮
      · 口型：按 currentTime 在 visemes.json 插值 → setViseme()
      · 动作：按 currentTime 命中 actions.json 段 → playMotion()
后端: 推 song.tick{t} 心跳（仅状态同步/纠偏，不用来逐帧渲染）
唱完: 后端推 song.end → 前端进入 finale
```
> 为什么合唱期不逐帧推口型、而用前端音频时钟？
> 音频播放与对口型必须**零漂移**；网络抖动不能让嘴对不上声音。所以让 `<audio>` 当权威，
> visemes/actions 是**预烘焙**的时间轴，前端按本地时钟查表渲染。
> WebSocket 仍承担"实时推流"：对白 TTS 口型帧（幕一/幕三）是**实时推**的，控制与事件也走 WS。

### 幕三 · 收尾 `finale`
```
后端: TTS 生成 Angela 点评/告别 → 同幕一，推 tts.* / viseme.frame* / subtitle
前端: 播放、对口型、字幕；可选回到 select
```

## 4. 主时钟与同步模型（关键决策）

| 场景 | 时间权威 | 口型来源 | 动作来源 |
|------|----------|----------|----------|
| 合唱 `singing` | 前端 `<audio>` `currentTime` | 预烘焙 `visemes.json`（按 t 插值） | 预烘焙 `actions.json` |
| 对白 TTS（幕一/三） | TTS 音频播放时间 | 后端实时推 `viseme.frame` | 后端 `action.set`（如 `talk`） |

- **合唱期**：WS 只下发**整条轨道**（或其文件路径）+ 心跳/事件，不逐帧推口型 → 抗网络抖动、嘴音不漂。
- **对白期**：TTS 是后端临时生成的，口型必须后端**实时推** → 体现"实时推流"价值。
- 这套混合模型把"零漂移渲染"和"实时推流"都照顾到。详见 `02-接口契约.md` §主时钟。

## 6. 技术决策记录（ADR 摘要）

| # | 决策 | 理由 |
|---|------|------|
| ADR-1 | 前端选 Web | 3 小时内最快搭出"视频+歌词+数字人"叠加，跨平台、好整合 |
| ADR-2 | 数字人用 Live2D（pixi-live2d-display） | VTuber 风格契合"虚拟少女"；Web SDK 直接跑在舞台里；口型/动作参数成熟 |
| ADR-3 | 数字人是**前端组件**而非独立进程 | 与舞台同进程，省掉跨窗口同步；接口即 JS API |
| ADR-4 | 通信用 WebSocket | 控制信令 + TTS 口型帧需要低延迟双向；合唱期仅心跳 |
| ADR-5 | 合唱渲染以**前端音频时钟**为权威 | 嘴音零漂移，抗网络抖动 |
| ADR-6 | TTS 用 edge-tts，可选 RVC 上色 | edge-tts 免部署、出声快；RVC 复用现有 Angela 模型让音色统一 |
| ADR-7 | 分轨用 Demucs，高低声部**人工编排** | 稻香非对唱，自动分声部不可靠；人工切/复制+移调最稳 |
